# DevBridge AX 백엔드 코딩 컨벤션

## 1. 패키지 구조

```
src/main/java/com/devbridge/backend/
├── api/                          # 컨트롤러 (API 진입점)
│   ├── auth/
│   ├── workspace/
│   ├── chat/
│   ├── notification/
│   ├── schedule/
│   └── task/
├── domain/                       # 도메인 로직
│   ├── user/
│   │   ├── entity/
│   │   ├── dto/
│   │   ├── repository/
│   │   └── service/
│   ├── workspace/
│   ├── chat/
│   ├── notification/
│   ├── schedule/
│   ├── task/
│   └── datasource/
└── global/                       # 공통 설정, 유틸리티
    ├── common/                   # BaseEntity 등
    ├── config/                   # SecurityConfig, JpaConfig 등
    └── exception/                # GlobalExceptionHandler
```

### 원칙
- `api/` 패키지는 HTTP 요청/응답만 담당. 비즈니스 로직 금지.
- `domain/` 패키지는 서비스 레이어에서 비즈니스 로직 처리.
- 도메인 간 의존은 서비스 인터페이스를 통해서만 허용. 엔티티 직접 참조 금지.
- `global/` 패키지는 도메인에 종속되지 않는 공통 기능만 배치.

## 2. 네이밍 컨벤션

### 클래스명
| 레이어 | 접미사 | 예시 |
|--------|--------|------|
| 컨트롤러 | Controller | WorkspaceController |
| API 인터페이스 | API | WorkspaceAPI |
| 서비스 | Service | WorkspaceService |
| 레포지토리 | Repository | WorkspaceMemberRepository |
| 엔티티 | (없음) | WorkspaceMember |
| DTO (요청) | Request | CreateWorkspaceRequest |
| DTO (응답) | Response | WorkspaceResponse |

### 메서드명
| 용도 | 패턴 | 예시 |
|------|------|------|
| 조회 (단건) | get + 대상 | getMeetingDetail |

### 변수명
- 엔티티 ID: `workspaceId`, `meetingId` (카멜케이스)
- Boolean: `is` 접두사 — `isRead`, `isFaq`
- 컬렉션: 복수형 — `participants`, `notifications`

## 3. 엔티티 규칙

### BaseEntity
모든 엔티티는 `BaseEntity`를 상속한다.
```java
@MappedSuperclass
public abstract class BaseEntity {
    @CreatedDate
    private LocalDateTime createdAt;

    @LastModifiedDate
    private LocalDateTime updatedAt;

    private LocalDateTime deletedAt;  // soft delete
}
```

### 어노테이션 순서
```java
@Entity
@Table(name = "TABLE_NAME")
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@AllArgsConstructor
@Builder
public class EntityName extends BaseEntity {
    // ...
}
```

### ID 전략
- UUID 문자열: `@GeneratedValue(strategy = GenerationType.UUID)`
- 컬럼 정의: `@Column(name = "id", columnDefinition = "VARCHAR(36)")`

### 연관관계
- 기본 fetch: `FetchType.LAZY`
- N+1 방지: 필요 시 `@Query`에서 `JOIN FETCH` 사용
- 양방향 매핑은 최소화. 단방향 `@ManyToOne` 선호.

## 4. DTO 규칙

### 응답 DTO
- `@Builder` 패턴 사용
- `static from(Entity)` 팩토리 메서드로 엔티티 → DTO 변환
- 엔티티를 직접 반환하지 않는다

### 요청 DTO
- `record` 타입 사용 권장 (불변, 간결)
- Validation 어노테이션: `@NotBlank`, `@NotNull`, `@Size` 등

### 예시
```java
// 요청
public record CreateMeetingRequest(
    @NotBlank String title,
    int durationMinutes,
    List<String> participantEmployeeIds
) {}

// 응답
@Builder
public class WorkspaceResponse {
    private String id;
    private String name;
    private String myPermission;
}
```

## 5. 서비스 규칙

### 트랜잭션
- 조회: `@Transactional(readOnly = true)`
- 변경: `@Transactional`
- 서비스 클래스 레벨이 아닌 메서드 레벨에 적용

### 예외 처리
- 비즈니스 검증 실패: `IllegalArgumentException` + 한국어 메시지
- GlobalExceptionHandler에서 일관된 에러 응답 포맷으로 변환
- 예외 메시지는 사용자에게 노출 가능한 수준으로 작성

### 권한 검증
- 워크스페이스 멤버십: `WorkspaceService.validateMembership()`
- 워크스페이스 권한: `WorkspaceService.validatePermission()`
- 워크스페이스 유효성: `WorkspaceContextValidator.getValidWorkspace()`

## 6. 컨트롤러 규칙

### API 인터페이스 분리
- Swagger 어노테이션은 `*API` 인터페이스에 선언
- 컨트롤러는 인터페이스를 구현하고 위임만 담당
- 컨트롤러에 비즈니스 로직을 작성하지 않는다

### 인증 정보 추출
- `@AuthenticationPrincipal`에서 `employeeId` 추출
- 워크스페이스 ID는 `@RequestHeader("X-Workspace-Id")`

## 7. 테스트 규칙

### 테스트 레이어
- 컨트롤러 테스트: `@WebMvcTest` + MockMvc
- 서비스 테스트: `@ExtendWith(MockitoExtension.class)` + Mock
- 통합 테스트: `@SpringBootTest` + H2 (create-drop)

### 테스트 메서드 네이밍
- 한국어 허용: `createMeeting_참석자에게_알림이_전송된다()`
- 패턴: `메서드명_조건_기대결과`

### 테스트 데이터
- 테스트 환경: H2 인메모리 DB (`application.yml` for test)
- `data.sql`은 테스트에서 실행하지 않음 (`sql.init.mode: never`)
- 테스트별 필요 데이터는 `@BeforeEach`에서 직접 생성
