# DevBridge AX 요구사항 정의서 v1.2

## 1. 프로젝트 개요

### 1.1 프로젝트 목표
DevBridge AX는 소프트웨어 개발 프로젝트에서 신규 투입 인력이 프로젝트를 빠르게 이해하고, 팀 간 협업을 AI 기반으로 자동화하는 시스템이다. 기존 프로젝트 산출물(기획서, 설계서, 회의록, Git 커밋 이력 등)을 RAG(Retrieval-Augmented Generation) 방식으로 인덱싱하여 챗봇을 통해 질의응답을 제공한다.

### 1.2 핵심 사용자
- **신규 투입 개발자**: 프로젝트 구조, API 스펙, 코딩 컨벤션 등을 빠르게 파악
- **기획자/PM**: 요구사항 변경 이력 추적, 업무 배정 현황 파악
- **QA 엔지니어**: 테스트 대상 기능의 명세 확인, 변경 영향도 분석
- **디자이너**: UI/UX 관련 요구사항 및 와이어프레임 참조

### 1.3 시스템 구성
- **Spring Boot 백엔드**: 인증, 워크스페이스 관리, 업무 관리, 알림
- **FastAPI AI 엔진**: RAG 기반 질의응답, 문서 인덱싱, Git 커밋 분석
- **Vue 3 프론트엔드**: 대시보드, 챗봇 UI, 일정 관리

## 2. 기능 요구사항

### 2.1 인증 및 사용자 관리 (AUTH)
- AUTH-001: 이메일/비밀번호 로컬 로그인 지원
- AUTH-002: Google OAuth2 소셜 로그인 지원
- AUTH-003: JWT 액세스 토큰(30분) + 리프레시 토큰(7일) 발급
- AUTH-004: 사용자 프로필에 직무(job_role) 정보 관리 — PLANNER, DEVELOPER, QA, DESIGNER, OPERATOR, NEWCOMER

### 2.2 워크스페이스 관리 (WS)
- WS-001: ADMIN 권한 사용자만 워크스페이스 생성 가능
- WS-002: 워크스페이스별 멤버 초대 (이메일 기반, MEMBER/GUEST 권한)
- WS-003: 워크스페이스 전환 시 대시보드 데이터 자동 갱신
- WS-004: 멤버 검색 API — 이름 기준 부분 일치 검색

### 2.3 대시보드 (DASH)
- DASH-001: 워크스페이스별 업무 현황 요약 (상태별 건수)
- DASH-002: 최근 Git 커밋 5건 표시 (커밋 메시지, 작성자, 시간)
- DASH-003: 연결된 데이터 소스 목록 (문서 저장소, Git 저장소)
- DASH-004: 미읽은 알림 건수 뱃지

### 2.4 AI 챗봇 (CHAT)
- CHAT-001: 워크스페이스 범위 내 RAG 기반 질의응답
- CHAT-002: 답변에 출처 문서 인용 표시 (citation)
- CHAT-003: 답변 신뢰도 점수 표시 (confidence_score)
- CHAT-004: AI가 답변 불가 시 담당자에게 확인 요청 자동 생성
- CHAT-005: 대화 세션 목록 관리 (생성, 조회, 삭제)
- CHAT-006: 담당자 답변 내용을 벡터화하여 지식 베이스에 누적

### 2.5 담당자 확인 (OWNER)
- OWNER-001: AI 챗봇이 신뢰도 임계값 미달 시 자동으로 담당자 확인 요청 생성
- OWNER-002: 담당자는 알림을 통해 확인 요청을 수신하고 답변 작성
- OWNER-003: 답변이 FAQ로 등록되면 이후 동일 질문에 자동 응답
- OWNER-004: 문서 상세 화면에서도 직접 담당자 확인 요청 가능

### 2.6 업무 관리 (TASK)
- TASK-001: 워크스페이스 내 업무 생성 (제목, 설명, 담당자, 마감일)
- TASK-002: 업무 상태 관리 — ASSIGNED, IN_PROGRESS, DONE, DELAYED
- TASK-003: 업무 배정 시 담당자에게 자동 알림 발송

### 2.7 일정 관리 (SCHEDULE)
- SCHEDULE-001: 회의 조율 요청 생성 (참석자 선택, 소요 시간 지정)
- SCHEDULE-002: 참석자별 가능 시간대 제출
- SCHEDULE-003: 전원 응답 시 AI가 최적 시간대 자동 추천
- SCHEDULE-004: 주최자가 확정 시간 선택 후 회의 확정
- SCHEDULE-005: 회의 상세에서 첨부파일(문서/링크) 관리

### 2.8 알림 (NOTI)
- NOTI-001: WebSocket 기반 실시간 알림 푸시
- NOTI-002: 알림 유형 — TASK_ASSIGNED, OWNER_CONFIRMATION_REQUESTED, OWNER_CONFIRMATION_ANSWERED, MEETING_INVITED, MEETING_UPDATED
- NOTI-003: 읽음/안읽음 상태 관리
- NOTI-004: 알림 클릭 시 관련 화면으로 네비게이션

## 3. 비기능 요구사항

### 3.1 성능
- API 응답 시간: 95th percentile 기준 500ms 이내
- 챗봇 응답 시간: SSE 스트리밍 기준 첫 토큰 2초 이내
- 동시 사용자: 워크스페이스당 최대 50명

### 3.2 보안
- 비밀번호: BCrypt 해싱 (cost factor 10)
- API 인증: JWT Bearer 토큰
- 워크스페이스 간 데이터 격리: workspace_id 기반 필터링
- AI 엔진 DB 접근: SELECT + 허용 테이블 DML만 부여

### 3.3 가용성
- 서비스 가용률: 99.5% (개발 환경 기준)
- Docker Compose 기반 단일 호스트 배포
- MySQL 데이터 볼륨 영속화
